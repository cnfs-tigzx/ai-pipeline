# 04 · 运行与降级

> 运行形态：单宿主进程。零常驻服务：不监听任何端口，不依赖 docker-compose，不依赖数据库服务。

## 一、运行形态

- **零常驻服务**：不监听任何端口，不依赖 docker-compose，不依赖数据库。
- **启动检查仅三项**：目录可写、config 可解析、模型密钥存在（缺失则进入离线模式）。
- **多实例**：同一台机可跑多个 runner，靠 `run_id` 与 mailbox 目录天然隔离；
  同一 run 只允许一个 runner 持有（`state.json` 加锁字段 `lock: {holder, heartbeat_ts}`，心跳超时视为孤儿可接管）。

```
宿主进程（runner.py）
 ├─ 加载 config/*.yaml（_yamlmini 子集解析）
 ├─ 初始化 capabilities 八个模块（进程内，无端口）
 ├─ 循环调度 data/mailbox 信封 + 活跃 run 的节点
 ├─ 按需拉起子进程：Agent（Cline act/plan 模式经 VSCode 交互；headless CLI 为演进位）、git、docker(可选)、浏览器
 └─ 落盘 data/
```

## 二、超时与重试（config/runtime.yaml 驱动）

| 项 | 默认 | 说明 |
|---|---|---|
| llm.timeout_s | 60 | 单次模型调用超时；失败按 models.yaml fallback 顺序重试 |
| llm.max_retries | 1 | fallback 之外的最大重试次数 |
| mailbox.deadline_default_s | 3600 | 信封默认处理时限，超时投递方写 .err.json |
| runner.poll_interval_s | 5 | mailbox 与活跃 run 轮询间隔 |
| node.max_retries | 2 | 节点级重试；超限按 on_fail: abort/skip/gate |

## 三、降级开关（三级）

1. **正常**：全能力可用。
2. **模型降级**：主模型失败 → fallback 模型；返回体带 `degraded=true`，上层据此降低自动化置信度（如方案中心改为出大纲转人工）。
3. **离线模式**：密钥缺失或全部模型不可用 → LLM 返回模板化占位文本（`degraded=true`）；
   文件信封、资产读写、记忆、trace、VCS、runtime 均照常工作；涉及模型调用的节点按 `on_fail` 处理（默认 gate 转人工）。

## 四、Agent 内核执行方式（第一阶段）

- 三中心智能体内核 = Cline（VSCode 扩展）+ 对应规则集：
  - 开发中心 → act 模式 + GLM 系列；方案中心 → plan 模式 + doubao 系列；数策中心 → deepseek 系列。
- 触发方式：人工在 Cline 会话加载 `agents/<center>/workflows/<wf>.md` 执行；产物按契约落盘。
- runner 第一阶段承担：flow 编排、mailbox 收发、脚本类节点（capabilities 子进程）执行；
  Cline 交互节点在 flow 中以 `node.type: agent_gate` 表达（人工完成后 gate 放行）。
- **演进位**：cline CLI headless 成熟后，agent 节点由 runner 直接拉起（评估记录见 archive/）。
