# 02 · 目录规范（三类数据严格分区）

## 一、三类数据分区

| 类别 | 位置 | 内容 | 入 git |
|---|---|---|---|
| 代码与契约 | docs/ config/ capabilities/ orchestration/ agents/ plugins/ scripts/ | 规则、配置、能力模块、流程定义、插件清单 | ✅ |
| 运行期落盘 | data/ db/ | 记忆、资产、轨迹、计量、信封、run 目录、SQLite 库 | ❌（gitignored） |
| 下游工作区 | repos/ | GitHub 拉取的工程源码、.auto-bak 备份 | ❌（gitignored） |

## 二、运行期目录细则

```
data/
├── memory/{eng,data,solution}/        # 契约2分区：shards/YYYY-MM.jsonl + index.json
├── assets/
│   ├── engineering/                   # 开发中心资产：{repo}/readme-parse.json、summary、dev-log
│   ├── datacenter/                    # 数策中心资产：datasets/（抓取表格、分析结果）
│   ├── solution/                      # 方案中心资产：manuals/、samples/、papers/
│   └── plugins/audit/                 # 工具调用审计：YYYY-MM-DD.jsonl
├── trace/<center>/<run_id>.jsonl      # 契约轨迹
├── usage/<center>/YYYY-MM.jsonl       # 模型计量（tokens/次数/耗时/降级标记）
├── mailbox/<from>_<to>/               # 文件信封（唯一跨中心通道）
├── runs/<run_id>/                     # state.json / log.jsonl / gate.json / runtime.json / vcs.log / artifacts/
└── tmp/                               # 抓取/构建临时区，可清理（保留 7 天）
db/                                    # 数策中心 SQLite：*.db（表结构见数策中心 rules）
```

## 三、命名规范

- run_id：`run-YYYYMMDDTHHMMSS-<4位随机>`
- req_id：`<run_id>-or<序号>`（无 run 的独立信封可用 `req-YYYYMMDDTHHMMSS-<4位随机>`）
- 资产 URI：`viking://<namespace>/<path>`，namespace ∈ {engineering, datacenter, solution, plugins}
- 工具名：`{slug}__{tool}`，slug 为插件目录名（小写中划线）
- 信封目录：`<from>_<to>`，from/to ∈ {eng, data, solution}
- 时间戳一律 ISO8601 本地时区 +08:00

## 四、Markdown 产物规范（承接原 00 §1.4）

- 禁止在产物 md 中写入 shell 注释（`#` 开头的非标题行）；标题用 `#`/`##`/`###`，正文不用 `#` 开头
- 超 50 行的代码/json/文档不得在对话中回显，必须写入磁盘
- 产物落位：开发中心产物 → `data/assets/engineering/`；方案/手册 → `data/assets/solution/`；表格/分析 → `data/assets/datacenter/`

## 五、YAML 写法限制（_yamlmini 子集）

- 两空格缩进；支持 map 嵌套（≤4 层）、`-` 列表项、标量（字符串/整数/浮点/bool）
- 支持行内与整行 `#` 注释；不支持锚点、多行块标量（`|`、`>`）、引号转义复杂场景、非空流式 map `{}`
- **单行流式数组 `[a, b, c]` 支持**（逗号分隔标量；不支持嵌套与引号内逗号）
- 字符串含特殊字符（`:` 后跟空格、`#`）时用双引号包裹
- 所有 config/*.yaml、plugins/*.yaml、flows/*.yaml 遵守此限制；runner 加载时报错即拒启（check 2/3）
