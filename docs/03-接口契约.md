# 03 · 接口契约与中心间文件协议

> 所有能力模块只通过 5 个契约被调用；中心之间不通网络，只投递文件信封。
> 契约是逻辑签名，不绑定具体语言与实现。第一阶段实现：`capabilities/` 下 Python 标准库单文件模块。
> 引用：02-目录规范.md（落盘位置）、04-运行与降级.md（超时与降级开关）。

## 契约 1 · LLM（替代 LiteLLM 网关）

```
complete(center, task, messages, options) -> { text, model, usage, latency_ms, degraded }
embed(center, texts, purpose) -> { vectors[], model }
```

- `center ∈ {eng, data, solution}`，决定路由优先级（读 `config/models.yaml`）。
- 内部完成：主模型选择 → 超时 → 失败按 fallback 顺序重试 → 计量落 `data/usage/<center>/YYYY-MM.jsonl`。
- 硬约束：任何模块与插件不得持有厂商密钥；密钥只由本模块从环境变量 `ARK_API_KEY` 读取（缺失时回退解析根目录密钥文件，禁止写入日志与任何被推送文件）。
- 输出必须带 `degraded` 标记（发生 fallback 时为 `true`），便于上层判断结果可信度。
- 全部模型不可用 → 进入离线模式：返回模板化占位文本且 `degraded=true`，由调用方决定是否转人工卡点。

## 契约 2 · Memory（替代 Mem0）

```
add(center, content, tags, meta) -> id
search(center, query, tags, limit, cross_domain=false) -> [{id, content, score, tags}]
update(id, patch) -> ok
forget(id, reason) -> ok
```

- `center` 决定分区（`data/memory/{eng,data,solution}/`）；`tags` 必填，至少含一个业务标签。
- `cross_domain=true` 时必须记录审计（谁、为什么跨区读），写入 `data/assets/plugins/audit/`。
- 写入自动去重：同 tag 且摘要相似度超过阈值时合并而非新增。
- 第一阶段实现：jsonl 分片（`shards/YYYY-MM.jsonl`）+ `index.json` + tag 匹配与关键词重合度评分（朴素检索，标注于 README，向量检索为演进位）。

## 契约 3 · Asset（替代 OpenViking）

```
write(namespace, path, content, meta) -> uri
read(uri, level) -> { content, level, meta }      # level ∈ L0 | L1 | full
list(namespace, prefix) -> [{uri, type, size, updated}]
stat(uri) -> meta
```

- `namespace ∈ {engineering, datacenter, solution, plugins}`。
- 写入同时更新 `manifest.json` 与 `index.jsonl`；覆盖写必须保留旧版本快照（版本号自增，存 `.versions/`）。
- 分层加载：上层 Agent 默认只读 L0（标题摘要）/L1（目录+首段），明确需要细节才 `level=full`，以控制上下文体积。
- URI 形如 `viking://<namespace>/<path>`（保持与历史资产寻址习惯兼容，仅为命名，不依赖 OpenViking 服务）。

## 契约 4 · Tool（替代 MCP Gateway）

```
list(center) -> { version, tools: [{name, description, side_effect, risk}] }
invoke(center, name, args) -> { ok, data, error, audit_id }
```

- `name` 必须形如 `{slug}__{tool}`；未在 `plugins/policy.yaml` 授权给该中心的插件一律不可见。
- `list()` 返回 `version`；启用/停用插件后版本 +1，调用方据此刷新工具清单（替代推送通知）。
- 每次 invoke 写审计：`data/assets/plugins/audit/YYYY-MM-DD.jsonl`（center / slug / tool / 参数哈希 / 行数 / 耗时 / 结果状态）。
- 高风险工具（数据库读、抓取）需在 args 中带 `run_id`，以便回溯到具体流水线。
- 分发方式：按 manifest 的 `entry`（command + args 模板）子进程直调，不走 MCP 传输层；MCP 声明仅保留为插件对外兼容格式（manifest 的 `compat.mcp` 字段）。

## 契约 5 · Orchestrator（替代 WeKnora 的流程承载位）

```
run(flow_path, inputs, run_id?) -> { run_id, status, artifacts[] }
status(run_id) -> { node, progress, state }
resume(run_id) -> continue | abort
gate(run_id, decision, note) -> ok          # 人工卡点放行/驳回
```

- 流程定义 YAML 中节点类型只允许引用契约 1~4 + `runtime` / `vcs` / `scrape`。
- 每个节点执行前后写 `data/runs/<run_id>/log.jsonl`；状态写 `state.json`，保证断点可续。
- 节点失败策略：`retry(n)` → 超限后按 `on_fail` 决定 `abort / skip / gate`（转人工）。
- 人工卡点：`gate.json` 落盘待批（`decision: pending|approved|rejected`），放行后继续。

## 中心间文件协议（替代 HTTP / MCP / 消息队列）

- 为什么用文件：三中心互不信任、都要可审计、单机无并发压力；文件信封天然可回放、可 diff、可离线。

### 投递位置

```
data/mailbox/<from>_<to>/<req_id>.req.json     # 请求
data/mailbox/<from>_<to>/<req_id>.res.json     # 结果
data/mailbox/<from>_<to>/<req_id>.err.json     # 错误
```

### 信封结构

```json
{
  "req_id": "run-20261108T101500-a1b2-or1",
  "run_id": "run-20261108T101500-a1b2",
  "from": "solution",
  "to": "data",
  "type": "read_data",
  "payload": { "need": "某行业近三年规模与增速", "format": "jsonnl" },
  "return_as": "viking://datacenter/datasets/xxx",
  "deadline": "2026-11-08T11:00:00+08:00",
  "trace": ["上游节点id"]
}
```

### 处理规则

1. 消费方按 `req_id` 原子「改名占用」（`.req.json` → `.req.lock`），处理完产出 `.res.json` 并删除 lock。
2. 超时未响应：投递方写 `.err.json` 标记 timeout，编排器按 `on_fail` 处理。
3. 所有信封保留 7 天，是唯一的跨中心调用凭证，审计查询优先读它。
4. 禁止任何 Agent 绕过编排器直接读取其他中心的 `data/memory` 或 `data/assets`。
