# 05 · 安全与确认策略

> 承接原 00-base-general.md 的安全约束，按零第三方架构裁剪。全部阶段生效。

## 一、确认策略（分级）

| 级别 | 操作 | 策略 |
|------|------|------|
| 低危 | 文件读取、页面抓取、搜索扫描、日志追加、git status、capabilities 自测 | 连续执行不等待 |
| 中危 | 文件写入、非破坏性脚本执行、git add/commit、资产写入、记忆写入、SQLite 建表 | 展示命令后执行不等待 |
| 高危 | docker compose up/down、批量文件修改、覆盖图片、rm -rf、docker system prune、git push --force、删除记忆/资产版本 | 打印完整命令，等待人工确认 |

- 阶段开始输出一次完整计划，步骤间不重复输出
- 高危命令完整列表：rm -rf、docker system prune、docker volume rm、git push --force、docker compose down（生产环境）
- 禁止自动执行高风险清理命令

## 二、安全红线

1. **工作边界**：仅在工程根目录内读写（下游 repos/ 属工作区）；禁止访问系统目录，不修改系统全局环境
2. **密钥隔离**：API Key/token/密码仅存 `local-secrets.md` 与密钥文件（均 gitignored）；llm.py 只从环境变量/密钥文件读取；禁止进入任何被推送文件、日志、对话输出、manifest
3. **跨中心隔离**：禁止任何 Agent 绕过编排器直接读取其他中心的 data/memory 或 data/assets；跨区读必须 cross_domain 审计
4. **备份回滚**：任何文件修改/覆盖之前备份到 `repos/{REPO}/.auto-bak/{时间戳}/[子目录/]`，保持原目录结构；
   编译/构建失败从备份恢复全部文件；native 模式终止进程并恢复文件，不保留损坏版本
5. **AGPLv3 红线**：OpenViking 类组件即使未来服务化，也只能独立进程 + API/MCP 调用，严禁源码合并

## 三、日志与输出规范

- 任务日志追加 `output/task-log.md`（时间、阶段、动作、结果）
- runner 运行日志：`data/runs/<run_id>/log.jsonl`（节点级）+ 控制台摘要
- git 同步日志：`output/git-push.log`（git-push.sh 内置）
- 推理模式：严谨、结构化，不发散

## 四、报告与产物章节模板

产物报告固定章节编号（按执行顺序追加，未执行的章节省略）：

1. 任务概要 2. 仓库路径与本地结构 3. 依赖清单 4. 启动命令 5. 访问地址 6. 风险点 7. 流水线执行记录 8. 部署验证 9. 产品说明书 10. 源码二次开发记录 11. Logo 与代码标识替换记录 12. 一键运维脚本说明 13. Git 自动化仓库管理脚本

- 落位调整：产物报告从 output/ 逐步过渡到 `data/assets/<所属中心>/reports/`；过渡期双写
